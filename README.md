## 빠른 시작

Node.js 22.12 이상을 권장합니다. Node.js 24에서도 개발 및 검증했습니다.

```bash
npm install
npm run dev
```

출력된 로컬 주소에서 방문객 화면을, 같은 주소의 `/admin.html`에서 Admin을 엽니다.

```bash
npm run build
npm run preview
```

배포 파일은 `dist/`에 생성됩니다. `index.html`과 `admin.html`을 각각 빌드하므로 SPA rewrite나 `404.html` 라우팅에 의존하지 않습니다. 파일 탐색기에서 HTML을 직접 실행하는 `file://` 방식은 지원하지 않습니다.

## GitHub Pages 배포

기본 배포는 GitHub Pages의 브랜치 배포입니다. 별도의 워크플로 쓰기 권한이 필요하지 않습니다.

1. `npm test`와 `npm run build:pages`를 실행합니다. Pages용 빌드 결과는 `docs/`에 생성됩니다.
2. 소스와 생성된 `docs/`를 함께 `carimatec-bsm/Carimatec-Rullet` 저장소의 `main` 브랜치에 올립니다.
3. GitHub 저장소의 **Settings → Pages → Build and deployment → Source**에서 **Deploy from a branch**, 브랜치 **main**, 폴더 **/docs**를 선택합니다.
4. GitHub의 기본 `pages build and deployment` 작업이 성공하면 위 주소에서 접속합니다.
5. 화면 코드를 바꾼 경우 `npm run build:pages` 후 `docs/` 변경도 커밋하고 push합니다. `docs/`는 빌드 시 다시 생성되므로 직접 편집하지 마세요.

Admin에서 바꾸는 공통 설정은 `public/data/event.json`을 직접 읽으므로 화면을 다시 빌드할 필요가 없습니다. `docs/data/event.json`은 마지막 빌드 시점의 네트워크 오류용 기본 사본입니다.

GitHub Actions 자동 빌드를 원할 경우 `deployment/github-pages-workflow.yml` 템플릿을 `.github/workflows/deploy.yml`로 옮기고 Pages Source를 **GitHub Actions**로 바꿉니다. 해당 파일을 push하려면 GitHub 인증에 워크플로 수정 권한이 필요합니다. 템플릿은 단위 테스트 후 `dist/`를 빌드·배포합니다.

### 저장소 이름 / base path 변경

`vite.config.ts`의 기본 `base`는 `'./'`입니다. 자산과 페이지 링크가 상대 경로이므로 저장소 이름이 바뀌어도 빌드 결과를 새 경로에 배포할 수 있습니다.

명시적인 경로를 쓰려면 다음처럼 설정합니다.

```bash
# macOS / Linux
VITE_BASE_PATH=/NewRepositoryName/ npm run build
```

```powershell
# Windows PowerShell
$env:VITE_BASE_PATH = '/NewRepositoryName/'
npm run build
```

사용자 Pages(`username.github.io`) 또는 커스텀 도메인의 루트에 배포하면 `/`를 사용할 수 있습니다. 저장소 이름·소유자가 바뀌면 `src/data/defaultConfig.ts`의 `REPOSITORY`도 함께 수정해야 공통 설정을 읽고 저장할 수 있습니다.

## 기기 간 공통 설정 저장

GitHub Pages 자체에는 서버 저장 기능이 없습니다. 이 프로젝트는 GitHub REST Contents API로 `public/data/event.json`을 커밋하여 **상품·이미지·초기 수량·행사·디자인 설정**을 공유합니다. 이 기능은 공개 저장소를 기준으로 합니다.

### 최초 한 번: GitHub 토큰 준비

1. GitHub의 **Settings → Developer settings → Personal access tokens → Fine-grained tokens**에서 토큰을 만듭니다.
2. Resource owner를 해당 저장소 소유자로, Repository access를 **Only select repositories → Carimatec-Rullet**로 지정합니다.
3. Repository permissions에서 **Contents: Read and write**를 부여합니다. 행사에 맞는 짧은 만료 기간을 정하세요.
4. Admin에서 **공통 설정 저장**을 누르고 토큰을 입력합니다. 토큰은 이 앱의 코드나 저장소에 붙여넣지 않습니다.

토큰은 React 메모리에만 유지하며 localStorage·sessionStorage·공개 JSON에 저장하지 않습니다. 저장 완료, 창 닫기, 로그아웃, 관리자 잠금 시 지웁니다. 토큰은 사용자가 지정한 이 저장소의 GitHub API에만 전송됩니다. 앱은 GitHub 계정 토큰을 대신 발급하거나 현장 PIN으로 GitHub 인증을 대체하지 않습니다.

- **이 기기에 저장:** 현재 브라우저에만 반영합니다. 공통 설정이 이 로컬 변경을 자동으로 덮어쓰지 않습니다.
- **공통 설정 저장:** GitHub에 커밋하고 현재 기기에도 적용합니다. 첫 접속·새로고침·수동 불러오기는 GitHub API에서 최신 설정을 확인합니다. 대기 화면은 60초마다 원본 CDN을 확인하고 5분마다 API를 다시 확인합니다. GitHub 원본 CDN은 이전 파일을 최대 5분 캐시할 수 있어 자동 반영에 약 1~5분이 걸릴 수 있습니다. 이전 버전으로 되돌아가는 것은 차단합니다. API 호출 제한이나 네트워크 오류 시 CDN 또는 기기에 저장된 설정을 사용합니다.
- **최신 설정 불러오기:** 편집 내용과 로컬 전용 설정을 버리고 GitHub 설정을 다시 적용합니다. 확인창이 표시됩니다.
- 다른 관리자가 먼저 저장한 경우 revision과 SHA를 검사해 덮어쓰기를 차단합니다. 로컬 저장 후 페이지를 다시 열어도 이전 공통 revision을 유지합니다. 설정 JSON을 백업하고 최신 설정을 불러온 뒤 다시 수정하세요.
- 회전 또는 결과 확인 중에는 해당 참여자의 룰렛 설정을 고정합니다. 설정 저장·재고 초기화도 진행 중 결과 확인 이후에 가능합니다.

이 저장소는 공개이므로 상품 수량과 확률도 소스에서 확인할 수 있습니다. 화면에서 확률을 숨기는 것은 서버 수준의 정보 보호가 아닙니다.

## GitHub 토큰 없이 설정 게시하기

1. 관리자에서 설정을 수정하고 **운영 및 데이터 → 설정 JSON 내보내기**를 누릅니다.
2. 다운로드 이름은 **event.json**입니다. 게시용 ISO 날짜 revision이 자동 생성되고 기기 전용 메타데이터와 참여 기록은 제외됩니다. 파일명을 바꾸지 마세요.
3. GitHub 웹에서 `public/data/event.json`과 `docs/data/event.json`을 이 파일과 동일한 내용으로 교체한 뒤 커밋합니다. 로컬 작업이라면 `public/data/event.json` 교체 후 `npm run build:pages`로 `docs/`를 생성하고 함께 커밋·푸시합니다.
4. 배포 성공 후 운영 기기의 Admin에서 **운영 및 데이터 → 최신 공통 설정 불러오기**를 실행합니다. 기기별로 저장한 설정은 자동 덮어쓰기를 하지 않으므로 이 단계가 필요합니다.

전체 기기 백업은 참여 기록을 포함할 수 있으므로 공개 GitHub에 업로드하지 마세요. 내보내기만으로 공통 저장되지는 않습니다. GitHub 웹 로그인 또는 로컬 Git 인증은 여전히 필요하지만 앱에 토큰을 입력할 필요는 없습니다.

## 방문객 경품 목록과 등수 설정

가로 화면은 안내·시작 버튼 / 중앙 룰렛 / 오른쪽 경품 목록으로 구성됩니다. 목록에는 룰렛과 동일한 상품의 전체 이름, 이미지, 섹터 색상이 자동으로 표시됩니다. 작은 화면에서는 **전체 경품 보기**로 모든 상품을 확인할 수 있습니다.

Admin → **경품 관리 → 등수 / 구분**에서 `1등`, `2등`, `특별상`, `참여상` 등을 12자 이내로 입력합니다. 빈칸은 관리자 상품 등록 순서에 따른 등수(꽝 상품은 `꽝`)로 표시합니다. 등수 문구는 표시용이며 상품 순서·확률·재고에 영향을 주지 않습니다. **공통 설정 저장** 또는 **event.json 내보내기 후 게시**로 다른 기기에도 공유됩니다. 기존 JSON에 등수 필드가 없어도 그대로 사용할 수 있습니다.

## 룰렛 상품 이미지 배치 조정

업로드 권장 규격은 **600×600px 투명 PNG**이며 기존 업로드/압축 방식은 유지합니다. SVG의 `preserveAspectRatio="xMidYMid meet"`로 이미지 전체 비율을 보존합니다. 이미지 위치는 섹터 중앙 각도로 계산하고 회전량을 역보정하여 회전 중에도 이미지는 화면 기준 정방향을 유지합니다.

`src/utils/wheelLayout.ts`에서 `PRIZE_IMAGE_SIZE_RATIO`, `PRIZE_IMAGE_RADIUS_RATIO`, `PRIZE_TEXT_MIN_RADIUS_RATIO`를 조정할 수 있습니다. 5개 상품 기준 기존 54단위에서 약 92.5단위(약 1.7배)로 커집니다. 이미지 정사각형을 둘러싼 원이 섹터와 룰렛 외곽을 넘지 않도록 상한을 계산하므로 상품 수가 많을 때는 자동으로 축소됩니다. 이름/확률/설명은 중앙 로고 바깥쪽의 별도 공간에 배치됩니다.

## 참가 흐름과 QR 설문

방문객은 **룰렛 돌리기 → QR 설문 참여 완료 확인 → 회전 → 결과 확인 → 다음 참여자** 순서로 이용합니다. QR 설문의 실제 완료 여부를 조회하거나 중복 참여를 검증하지 않습니다. 부스 운영자가 설문 참여 기록을 확인하는 운영 방식입니다.

개인정보 동의는 별도 QR 설문에서 받도록 요청에 따라 이 페이지의 동의 문구와 동의 체크박스는 제외했습니다. 개인정보를 반복해서 입력하지 않도록 방문객 정보 입력은 기본 OFF입니다. 따라서 기본 기록은 시간·참가 ID·당첨 상품 중심이며 이름·회사·연락처·이메일은 빈 값입니다.

필요할 때 **이벤트 설정 → 룰렛 참여 전 방문객 정보 입력받기**를 켜고 필수 항목을 선택할 수 있습니다. 수집 내용에 맞는 외부 설문 동의가 완료된 운영 환경에서 사용하세요. 설문 URL을 입력하면 참여 확인창에 외부 설문 링크가 표시됩니다. QR 코드 자체 생성이나 설문 DB 연동은 포함하지 않습니다.

## 기록·재고의 저장 범위

| 데이터                              | 저장 위치                    | 기기 간 공유      |
| ----------------------------------- | ---------------------------- | ----------------- |
| 상품명·이미지·설명·확률·초기 수량   | GitHub 공통 JSON / 기기 캐시 | 공통 저장 시 공유 |
| 행사명·기간·디자인·운영 옵션        | GitHub 공통 JSON / 기기 캐시 | 공통 저장 시 공유 |
| 참가자 개인정보·참가 시간·당첨 기록 | 현재 브라우저 localStorage   | 공유하지 않음     |
| 실제 소진 수량·진행 중 결과         | 현재 브라우저 localStorage   | 공유하지 않음     |
| GitHub 토큰                         | 입력한 관리자 화면의 메모리  | 저장하지 않음     |

**여러 기기의 실시간 통합 재고는 지원하지 않습니다.** 경품 총량을 한 대의 스탠바이미에서 운영하거나 기기별로 수량을 나누세요. 통합 고객 DB, 원격 기록 조회, 전역 재고, 확실한 중복 방지에는 별도 인증 백엔드가 필요합니다. 공개 GitHub 저장소에 개인정보를 올려 이 제약을 우회하지 않습니다.

같은 기기라도 브라우저·브라우저 프로필·도메인이 다르면 기록이 다릅니다. Admin의 CSV는 **룰렛을 진행한 장비의 같은 브라우저**에서 내려받아야 합니다. 브라우저 데이터 삭제·시크릿 창 종료 시 기록이 사라질 수 있으므로 현장 운영은 일반 창을 사용하세요. CSV를 내려받을 수 없는 TV 브라우저라면 운영 전에 다른 장비로 백업할 방법을 실기에서 확인해야 합니다.

### 저장 안정성

- 당첨 결과를 먼저 결정하고 **기록·재고·진행 중 결과를 하나의 localStorage 쓰기**로 확정한 뒤 회전합니다.
- 회전 중 새로고침하거나 페이지를 닫았다 열어도 동일한 당첨 결과를 복구합니다. 추첨과 재고 감소를 반복하지 않습니다.
- 저장 공간 부족 또는 저장 차단 시 추첨 결과를 확정하지 않고 오류를 알립니다.
- 훼손된 저장 데이터를 감지하면 자동 삭제하거나 초기화하지 않고 오류를 표시합니다.
- 중복 터치를 차단하며 같은 브라우저 탭 간 짧은 잠금도 사용합니다. 현장 룰렛은 하나의 탭에서 운영하는 것을 기준으로 합니다. 이는 분산 DB 트랜잭션을 대체하지 않습니다.
- 이미지 업로드는 FileReader로 읽고 Canvas로 최대 300px 수준으로 압축하여 DataURL로 보관합니다. 파일당 최대 10MB 원본을 허용하며 지원 형식은 PNG/JPG/WEBP입니다. 큰 이미지와 장기간 누적 기록은 브라우저 저장 용량에 영향을 줍니다.

### 재고 처리

남은 재고는 `초기 수량 - 이 기기의 소진 수량`입니다. 초기 수량을 수정해도 이미 지급한 소진 수량은 유지됩니다. 재고 0인 상품은 추첨에서 제외하며, 자동 재분배가 켜져 있으면 남은 당첨 가능 상품의 가중치 비율대로 재분배합니다. 체크를 해제하면 양의 확률을 가진 활성 상품 중 하나라도 소진되었을 때 참여를 중지합니다. 칸은 시각적 안정성을 위해 그대로 유지됩니다.

**운영 및 데이터 → 참여 기록·상품 수량 초기화** 버튼 하나로 통합되어 있으며 실행 전 확인창을 거칩니다.

- 이 기기의 모든 이벤트 참여 기록을 삭제하고 소진 수량을 0으로 함께 되돌립니다. 잔여 수량은 저장된 상품별 초기 수량으로 복구됩니다.
- 상품 목록·이름·이미지·확률·초기 수량·이벤트 설정·공통 설정 버전은 변경하지 않습니다. 수정 중인 관리자 입력도 유지됩니다. 기본 예시 상품으로 되돌리는 전체 설정 초기화 기능은 없습니다.
- GitHub 파일이나 다른 기기의 데이터는 변경하지 않습니다. 별도 공통 저장이나 GitHub 토큰도 필요 없습니다.
- 진행 중인 참여/미확인 결과가 있으면 초기화를 차단합니다. 기록·소진 수량을 한 번에 저장하여 부분 초기화를 방지합니다.
- 기록은 되돌릴 수 없으므로 CSV 또는 기기 전체 백업을 먼저 보관하세요. 기능 업데이트 자체가 기록을 삭제하지는 않으며 운영자가 확인창에서 실행해야 초기화됩니다.
- 이벤트 ID 변경: 새 행사의 소진 수량을 0에서 시작합니다. 이전 참가 기록은 유지합니다.

## CSV와 통계

참여자 목록에서 검색·페이지 이동·CSV 다운로드를 지원합니다. CSV는 **UTF-8 BOM + CRLF**이며 Excel 한글 표시를 지원합니다. 셀 인용부호·쉼표를 이스케이프하고 스프레드시트 수식 실행 문자를 중립화합니다. 검색 중 다운로드하면 검색 결과만 내려받습니다. 연락처의 선행 0을 엄격히 보존해야 하는 경우 Excel의 데이터 가져오기에서 연락처 열을 텍스트로 지정하세요.

대시보드는 현재 이벤트 ID의 오늘 참여자, 총 참여자, 꽝을 제외한 당첨 건수, 상품별 횟수·잔여 재고를 표시합니다. 참여자 목록은 모든 이벤트 기록을 보존합니다. 데이터가 없는 첫 실행은 0으로 표시합니다.

설정 JSON은 내보내기·가져오기를 지원합니다. 전체 기기 백업 JSON에는 참여 기록·소진 재고·진행 중 결과도 들어가므로 안전하게 보관하세요. 설정 가져오기는 설정 전용 파일만 허용하며 자동 저장하지 않습니다. 전체 기기 백업의 자동 복원 UI는 제공하지 않습니다.

## 로고·폰트

- 로고: `public/assets/logo.png`. 파일이 없거나 읽지 못하면 CARIMATEC 텍스트로 표시합니다.
- Gotham-Bold: 웹폰트 라이선스를 보유한 `Gotham-Bold.woff2`를 `public/assets/`에 넣고 다시 빌드하면 자동 적용합니다. 개발 서버 사용 중 추가했다면 재시작하세요.
- 폰트 파일이 없어 기본 제공하지 않습니다. 설치된 Gotham-Bold 또는 Arial 및 시스템 한국어 글꼴을 사용합니다.
- 데모 경품 일러스트는 `public/assets/prize-*.svg`입니다. Admin에서 업로드한 이미지는 설정 JSON의 DataURL로 대체합니다.

## 관리자 PIN

`src/data/defaultConfig.ts`의 `ADMIN_PIN`을 변경하고 다시 배포하면 기본 PIN이 바뀝니다. 정적 사이트이므로 PIN은 일반 방문객의 우발적 접근을 막는 편의 기능이며 소스 분석에 대한 보안 장치가 아닙니다. 5회 실패 시 30초 입력 제한, 15분 미사용 시 자동 잠금을 제공합니다. GitHub 쓰기 권한과는 별개입니다.

## LG 스탠바이미 1 운영

- 가로 1920×1080, 세로 1080×1920 및 작은 태블릿·모바일 크기에 반응합니다.
- 큰 시작 버튼, 터치 피드백, 중복 터치 방지, 모달 내 포커스 이동, 키보드 조작을 제공합니다.
- 방문객 화면은 단일 화면에 맞추고 선택·드래그·더블탭 확대를 억제합니다. 입력 폼과 긴 관리자 페이지는 필요한 스크롤을 허용합니다.
- 전체 화면 버튼은 브라우저가 Fullscreen API를 지원할 때 동작합니다. 지원하지 않으면 브라우저 메뉴 안내를 표시합니다.
- 소리는 기본 OFF입니다. 향후 효과음은 `carimatec-wheel-tick` 이벤트에 연결할 수 있습니다.
- JS는 Chrome 79 타깃으로 빌드합니다. SVG, CSS transform, requestAnimationFrame을 사용하고 네트워크가 끊겨도 이미 열린 페이지는 캐시된 설정과 로컬 저장으로 계속 운영합니다. 오프라인 최초 접속이나 네트워크가 없는 상태에서의 새로고침은 보장하지 않습니다.
- 실제 LG 스탠바이미 하드웨어는 개발 환경에 연결되어 있지 않아 실기 검증은 포함하지 못했습니다. 행사 전 해당 장비에서 터치·한글 입력·이미지 업로드·CSV 다운로드·화면 회전·브라우저 재시작을 한 번 확인하세요.

## 테스트

```bash
npm test
npm run build
npm run test:e2e
```

브라우저 테스트는 설치된 Google Chrome를 headless로 사용합니다. 다른 환경은 `playwright.config.ts`의 `channel: 'chrome'`을 제거하고 `npx playwright install chromium`을 실행할 수 있습니다.

- 단위 테스트: 확률 경계값, 100,000개 표본 구간의 가중치 분포, 2~12개 전 영역·offset의 정확한 정지, 재고 제외, 한국 시간 행사 기간, 검증, UTF-8 BOM CSV, 공개 필드 제한, 저장 용량 오류, 동시 참여, 재시작 복구.
- 브라우저 테스트: 실제 5초 회전과 포인터 일치, 새로고침 복구, PIN, Admin 저장, 이미지 업로드, 선택적 고객 정보, CSV 파일 바이트, 소진 재고, 초기화 확인, 가로·세로·모바일 터치 배치.
- GitHub 쓰기·충돌·기기 공유의 자동 테스트는 API 모의 응답을 사용합니다. 사용자가 발급한 실제 PAT를 테스트 코드에 저장하지 않습니다.

테스트 캡처와 브라우저 추적은 `.qa/`, `test-results/`에 생성되며 GitHub에 업로드하지 않습니다.

## 구조

```text
src/
  App.tsx                   방문객 상태 흐름과 애니메이션
  components/               로고, 룰렛 SVG, 참여 폼, 결과, 모달
  admin/                    대시보드, 상품 편집, 참가 목록
  data/defaultConfig.ts     기본 설정, PIN, 저장소 연결 정보
  utils/
    rouletteLogic.ts        가중치 추첨, 재고, 정지 각도
    storage.ts              로컬 저장, 추첨 트랜잭션, 복구
    github.ts               공통 설정 읽기/쓰기, 충돌 검사
    validation.ts           외부 JSON 및 관리자 설정 검증
    imageUpload.ts          이미지 읽기 및 압축
    csvExport.ts            BOM CSV와 다운로드
  styles/index.css          방문객·운영자 반응형 스타일
public/
  data/event.json            모든 기기가 읽는 공개 공통 설정
  assets/                   로고 및 기본 이미지
tests/unit/                 핵심 로직 검증
tests/e2e/                  실제 브라우저 시나리오
```

저장 로직과 UI는 분리되어 있습니다. Firebase/Supabase 도입 시 `storage.ts`, `github.ts` 계층을 인증된 서버 저장소로 교체하고 서버에서 결과 확정·전역 재고·참가 이력을 원자적으로 처리하는 구조로 확장할 수 있습니다.

공식 배포/API 참고: [Vite GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages), [GitHub Contents API](https://docs.github.com/en/rest/repos/contents#create-or-update-file-contents).
